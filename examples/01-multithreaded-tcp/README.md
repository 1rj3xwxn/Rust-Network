# 01 - 多线程 TCP 通信

这是 Rust-Network 的第一个可运行 TCP 实践项目：一个服务端、一个客户端，服务端为每个连接创建一个操作系统线程。

## 运行环境

需要安装 Rust 工具链。打开两个终端，并将当前目录切换到本项目目录：

```bash
cd examples/01-multithreaded-tcp
```

## 启动服务端

终端一：

```bash
cargo run --bin server
```

## 启动客户端

终端二：

```bash
cargo run --bin client
```

可以再开一个或多个终端启动客户端，观察服务端如何同时处理多个连接。

客户端输入一行文本并按 Enter，服务端会打印收到的消息，并返回一行响应。输入 `/quit` 退出客户端。

## 当前版本的设计

- 使用 `TcpListener::bind` 监听本机的 `127.0.0.1:7878`。
- 使用 `listener.incoming()` 接受 TCP 连接。
- 每接受一个连接，就使用 `thread::spawn` 创建一个线程。
- 每个连接线程独立处理该客户端的文本消息。
- 使用换行符作为本练习的消息边界；客户端每次发送一行，服务端通过 `BufReader::read_line` 读取一行。
- 使用 `try_clone` 克隆 TCP 流句柄，让读取缓冲器和写入端分别持有句柄；它们仍指向同一个 TCP 连接。

## 当前版本的局限

这是用于学习的基础版本，不是生产级服务器：

- 每个连接创建一个线程，没有线程池。
- 没有连接数限制、读写超时或空闲连接回收。
- 没有身份认证、加密和访问控制。
- 没有定义复杂消息协议；当前只处理 UTF-8 文本行。
- 服务端没有优雅关闭机制。

## 后续迭代顺序

1. 增加连接编号，观察多个客户端的连接生命周期。
2. 增加客户端数量和连接数统计。
3. 增加读写超时，并理解客户端断开、异常断开和半关闭。
4. 把“每连接一个线程”改为固定大小的线程池。
5. 设计带长度字段的消息协议，摆脱仅靠换行符分帧。
6. 再把服务端改造成 Tokio 异步版本，对比线程模型和异步任务模型。

每一步先解释原理，再由学习者修改代码，最后通过测试验收；不要一次性把后续功能全部加进来。
